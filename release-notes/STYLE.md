# 开发版更新说明写作规范

读者是正在写论文的模板使用者。报告说明实际变化及使用方法，事实来自本次变更、维护者说明和真实编译结果。

## 固定结构

PDF 和 Markdown 共用以下顺序，由程序生成标题和栏目：

1. 版本、北京时间日期和“此预览由 AI 比对生成”。
2. 本次概览：简述本次实际变化。
3. 更新内容：每条按“变化、适用范围、旧稿处理、已确认示例、真实对照”的顺序排列。
4. 升级提示：说明如何阅读各条的旧稿处理要求。
5. 下载与手册：由程序填写当前版本的真实链接；未发布预览不生成发布链接。

模型只填写受约束的 JSON 字段。条目类型限为新增、修复、调整、维护；旧稿处理限为无需修改、可选设置、必须修改、待确认。字段长度和条目数量以 `scripts/dev-report-style.py` 为准。

示例代码和图片只通过已登记的编号引用。没有示例或对照时不补造；影响范围不明确时留空，由程序显示待确认。必须修改旧稿的条目须引用维护者明确标为不兼容的证据，并给出已确认的操作步骤。

## 语言

- 直接写具体对象和行为，例如“关键词续行与正文左边界对齐”，不要只写“优化排版”或“提升体验”。
- 用简短陈述句，一句话只说一件事；一个字段是一段普通文本，群消息可用少量短段落。
- 标题用简短名词或动作短语，不带句号，不写宣传标题。
- 命令名称、宏包名、参数名和取值保留原文；中文与英文、数字之间留半角空格。
- 正文不写 LaTeX 反斜杠代码、Markdown 标题、代码块、图片路径、链接或聊天机器人命令。代码只引用维护者给出的示例编号。
- 描述默认行为、可选设置和必须迁移时分别说明。不能把保留旧外观的可选设置说成旧用法失效。
- 不写“重磅”“全面升级”“赋能”“保驾护航”“焕然一新”“显著提升”等宣传或空泛评价；不写“值得注意的是”“综上所述”等凑字数的引导句。
- 不写 CI、PR 流程、测试数量、提交哈希、版本计算方法或维护过程。真实功能和使用步骤可以写。
- 不编造结果、适用范围或操作步骤，不以“全面兼容”“绝对稳定”等无依据保证代替事实。
- 同一变化只解释一次，不把提交日志改写成多条重复说明。

## 示例

推荐标题：`关键词续行对齐`

推荐描述：`关键词超过一行时，续行与正文左边界对齐。`

推荐范围：`包含多行关键词的中英文论文。`

可选设置：`需要保持原来的悬挂样式时，可使用下方示例。`

不采用：`本次重磅升级全面优化了关键词排版，显著提升论文写作体验。`

## 校验

结构、枚举、长度、长句、重复条目、中英文空格、禁用措辞、内部维护信息和证据覆盖都先经程序检查。模型正常生成一次；失败时最多根据具体错误纠正一次，仍不合格则停止发布。语言校验不能替代事实审阅，维护者仍需提供准确的变更事实、影响范围和使用示例。
